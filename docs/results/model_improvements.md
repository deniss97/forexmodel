## 1. Формула EV по барьерам разметки и стоп 2 ATR

Было: формула ожидаемой ценности `p·TP − (1−p)·SL − комиссия` брала `simulation.tp_atr / sl_atr`.
Но `p` — вероятность класса, размеченного по барьерам `labeling.tp_atr / sl_atr` (1.5 / 0.75): модель
отвечает на вопрос про них, а не про стоп выхода. Побочный эффект: расширение стопа до 1.5–2 ATR
поднимало требуемую `p` и обнуляло сделки (RESULTS.md, часть III).

Теперь: `simulation.ev_tp_atr / ev_sl_atr`, по умолчанию `null` → барьеры разметки. Стоп выхода
можно менять независимо. На сохранённых сигналах (без переобучения; «без 2» — итог без двух
лучших сделок):

## 2. Правило `net_large_delta` + CatBoost как фильтр (рекомендация 1а)

Прогон `lkoh_2024_orderflow_reg`, правило `of_large_delta_z_6 ≥ 1.5` (лонг) / `≤ −1.5` (шорт), без
EV- и тренд-фильтра, поверх — фильтр по выходам модели того же прогона:

| вариант | test: сделок / итог / PF | sim: сделок / итог / PF |
|---|---|---|
| правило z ≥ 1.5 (как в отчёте) | 258 / +8.58% / 1.17 | 98 / −0.97% / 0.95 |
| + CatBoost того же знака | 116 / −3.19% / 0.82 | 55 / −0.80% / 0.91 |
| + CatBoost не против | 196 / +8.76% / 1.24 | 84 / +0.70% / 1.04 |
| + `p_dir − p_opp ≥ 0` | 169 / +4.96% / 1.17 | 80 / +2.29% / 1.16 |
| + `p_dir ≥ 0.36` | 114 / −0.79% / 0.96 | 55 / −1.95% / 0.79 |
| + мета ≥ 0.50 | 78 / −4.99% / 0.63 | 26 / +0.48% / 1.15 |
| + тренд-фильтр по знаку | 60 / −1.00% / 0.91 | 22 / −2.81% / 0.55 |
| **правило z ≥ 2.0** | **169 / +2.55% / 1.07** | **66 / +3.68% / 1.31** |
| z ≥ 2.0 + CatBoost не против | 134 / +2.20% / 1.08 | 58 / +4.49% / 1.47 |
| модель cb без фильтров | 457 / +0.37% / 1.00 | 222 / −5.79% / 0.84 |

Модель как фильтр правила **не работает**: требование согласия с CatBoost режет сделки вдвое и
уводит в минус, «не против» даёт то же, что правило без фильтра. Это ожидаемо после разбора:
вероятности primary почти не различают направление. Единственное, что устойчиво в обоих окнах, —
более строгий порог самого правила (z ≥ 2: PF 1.07 / 1.31 против 1.17 / 0.95 при z ≥ 1.5). Вариант 1б
(отдельная направленная модель) остаётся открытым — см. раздел 4.

## 3. Мета-модель: почему вырождалась и что исправлено

Выход мета-модели на test по сохранённым сигналам:

| прогон | σ `meta_proba` | диапазон | доля > 0.55 |
|---|---|---|---|
| `silver_1h` | 0.0044 | 0.493–0.524 | 0 |
| `lkoh_2024_orderflow_reg` | 0.0081 | 0.461–0.525 | 0 |
| `lkoh_2024_base_reg` | 0.0260 | 0.389–0.553 | 0.2% |
| `lkoh_1h` | 0.0386 | 0.309–0.618 | 7.4% |

Причина — в логах обучения. OOF-предсказания primary для мета-выборки строились по 5 фолдам, и
**каждый фолд обучался на все `catboost.iterations` = 2000 деревьев без early stopping**
(learn-loss на фолдах падал до 0.30–0.49), тогда как боевая primary-модель после early stopping
по val имеет 66 деревьев (серебро) и learn-loss около 1.0. OOF-вероятности выходили экстремальными,
мета-модель училась отличать прибыльные сигналы среди *переобученных* предсказаний, а на инференсе
получала *другие* — мягкие — вероятности той же модели с 66 деревьями. Ответом на незнакомое
распределение стала константа около 0.5.

Исправление ([models/meta.py](../../forexmodel/models/meta.py), [pipelines/train_pipeline.py](../../forexmodel/pipelines/train_pipeline.py)):
фолды OOF обучаются с тем же числом деревьев, что у боевой primary после early stopping
(`iterations=primary.model.tree_count_`).

**Проверка переобучением (прогон `silver_direction`, см. раздел 4) показала, что этого мало.**
Мета-выборка стала репрезентативной (27 495 сигналов, доля прибыльных 0.446), но мета-модель
остановилась по early stopping на **2 деревьях** с ROC-AUC 0.528 на holdout — ровно как раньше.
То есть дефект OOF был реальным (и исправление правильное: мета обязана учиться на тех же
вероятностях, что увидит в бою), но не он делал мету константой: **в мета-задаче «прибыльна ли
сделка по этому сигналу» на серебре просто нет сигнала**, который CatBoost мог бы взять из тех же
85 признаков + вероятностей primary. Оставшиеся подозрения из рекомендации 5 (class_weights,
совпадение мета-признаков с признаками primary) теперь выходят на первый план: мета видит то же,
что primary, и ничего нового про исход сделки сказать не может. Кандидаты на мета-признаки, которых
у primary нет: исход последних N сделок, класс входа (продолжение / откат / нож, trade_review часть II),
режимные `vr4_*` / `acf1_*`, положение относительно гейта.

## 4. Направленная разметка и режимные признаки (рекомендация 1б) — подготовлено

Разбор сделок показал, что primary учится волатильности, а не направлению: это свойство
разметки «дойдёт ли до барьера 1.5 ATR раньше 0.75 ATR за 10 часов». Добавлен режим разметки
`labeling.mode: direction` ([labeling/direction.py](../../forexmodel/labeling/direction.py)):

    move = (close[i + 1 + horizon] − open[i + 1]) / atr[i]
    label = 2 при move ≥ dir_atr, 0 при move ≤ −dir_atr, иначе 1   (dir_atr = 0.5 по умолчанию)

Минутные данные для неё не нужны, `label_t1` = конец горизонта (для весов уникальности и embargo).

Добавлены режимные признаки `features.use_regime_features` ([features/extension.py](../../forexmodel/features/extension.py)):
`vr4_<w>` (variance ratio на 4 барах по прошлым w часам) и `acf1_<w>` (автокорреляция часовых
доходностей), окна 240 и 720 часов. По [профилю инструментов](instrument_profile.md) это
единственные режимные величины с согласованным знаком на серебре и LKOH за 10 лет: входы по тренду
лучше при низком VR за прошлый месяц.

Конфиг эксперимента — [configs/silver_direction.yaml](../../configs/silver_direction.yaml): разметка
`direction`, режимные признаки, сеть выключена (на серебре бесполезна), гейт C, стоп 2 ATR, EV по
разметке. Оба нововведения покрыты тестами на каузальность
([tests/test_direction_and_regime.py](../../tests/test_direction_and_regime.py)). Запуск:

```bash
python -m forexmodel.cli run -c configs/silver_direction.yaml --split sim
python -m forexmodel.cli backtest -c configs/silver_direction.yaml --split test
```

## 6. Что дальше, в порядке отдачи

1. **Walk-forward — теперь обязательная проверка любого изменения на серебре.** Планка: прибыльных
   лет больше половины и медиана года выше нуля; пара test/sim этого не показывает. Обучение
   занимает 2–3 минуты, 8 лет — 20 минут.
2. **Меньше полагаться на CatBoost как на источник направления.** Три разметки (барьеры, direction
   с пятью горизонтами и порогами) дают одну и ту же модель «про волатильность и час суток» с
   |p_long − p_short| ≈ 0.02–0.04. Направление задаёт гейт, и на серебре без него всё убыточно.
   Следующие кандидаты, которые не пробовались: регрессия хода в ATR вместо классов (рекомендация 6),
   и модель, обученная **только на барах внутри гейта** — сейчас 2/3 обучающих примеров приходятся на
   нейтраль, где сделок всё равно нет.
3. **Мета-модели нужны признаки, которых нет у primary**: класс входа (продолжение / откат / нож),
   исход последних сделок, режим `vr4_*`. Пока мета видит то же, что primary, она остаётся константой
   (раздел 3).
