## Что такое инференс и зачем он нам

Бэктест отвечает на вопрос «как стратегия торговала бы в прошлом». Инференс — «что делать сейчас»: каждый час на
свежих данных тот же код, что считал журнал экспериментов, выдаёт по каждой бумаге одно из решений:

* **ОТКРЫТЬ лонг по рынку** — со стопом, уровнем включения трейлинга и отступом;
* **держать; стоп X** — позиция стратегии открыта, X — текущий стоп с учётом трейлинга;
* **закрыто (трейлинг-стоп / стоп-лосс / по сроку)** — стратегия вышла за последние часы;
* **ничего**.

Код тот же, что у бэктеста, — ничего не переписано заново, поэтому решения совпадают с бэктестом по построению
(это проверено бумажным прогоном, см. ниже). Инференс нужен для трёх вещей:

1. сигналы для нашей ручной торговли — что купить, где поставить стоп и трейлинг, когда продать по сроку;
2. журнал решений — чтобы сверять наши сделки и поведение стратегии с бэктестом;
3. здоровье стратегии — раз в день метрики за 12 месяцев против порогов тревоги (H43).

## Как устроено сейчас

Каждый час в :05 (все дни, включая выходные — биржа торгует акциями и в выходные) cron запускает
`scripts/queues/live_hourly.sh`:

1. `scripts/fetch_tinvest.py` — дописывает новые завершённые минуты SBER, GAZP, LKOH из Т-Инвестиций (без задержки;
   без токена — бесплатный ISS биржи с задержкой 15 минут);
2. `scripts/live_signals.py` — решения по трём бумагам: отчёт и строка в журнале;
3. раз в день в 23:00 по Москве — `scripts/live_health.py`, здоровье стратегии.

Что и где сохраняется:

| файл | что в нём | когда пишется | в git |
|---|---|---|---|
| `data/raw/live/SBER_1m_live.csv` (и GAZP, LKOH) | все минутки с 2015 года: до мая–июня 2026 — выгрузка Тимура (moexalgo), июнь — 12.10 — ISS биржи, с 12.10 — Т-Инвестиции; ≈ 2 млн минут на бумагу, 518 МБ на три | раз в час дописываются новые минуты | нет |
| `reports/live/<дата>_<время>.md` | отчёт запуска: решение по каждой бумаге | каждый час | нет |
| `reports/live/journal.csv` | журнал решений: строка на бумагу на запуск | каждый час | нет |
| `reports/live/health.md` | здоровье стратегии: PF за 12 месяцев, просадка, итог против порогов | раз в день | нет |
| `reports/live/logs/<дата>.log` | что делал каждый запуск, ошибки | каждый час | нет |
| `configs/tinvest_token` | токен API, права только у владельца | вручную | нет (`.gitignore`) |

Минутки в git не лежат и пока нигде не копируются. Если файл пропадёт — историю можно бесплатно выкачать заново с
биржи (`python scripts/moex_data.py shares SBER --from 2015-01-01`), но это займёт около получаса на бумагу.

## Как торговать по отчёту руками

Пример — отчёт стратегии по LKOH на 25.08.2026 в 19:05:

```
ОТКРЫТЬ лонг по рынку (вход контура 08-25 19:01 по 4284); стоп 4036, трейлинг с 4408 с отступом 248.1
цена 4290 (+0.13%); ATR на входе 41.36; трейлинг включится на 4408; закрыть не позже 2026-09-04 19:01
```

1. **«ОТКРЫТЬ»** — купить по рынку в течение 30 минут после минуты входа (HH:01), на капитал этой бумаги. Позже
   сигнал превращается в «держать» — вход пропущен, догонять не нужно.
2. **Сразу после покупки — две стоп-заявки у брокера:** стоп-лосс на цене покупки − 6 ATR и трейлинг-стоп:
   включается на цене покупки + 3 ATR, отступ 6 ATR. В отчёте уровни посчитаны от цены входа стратегии; от своей
   цены их можно пересчитать по ATR из отчёта (на бумажном прогоне разница цен входа — 0.03%).
3. **«держать; стоп X»** — каждый час отчёт пишет текущий стоп с учётом трейлинга. Если трейлинг-стоп у брокера не
   ставили, стоп-лосс надо переставлять на X вручную.
4. **«закрыть не позже»** — срок 240 часов: если позиция ещё открыта, продать по рынку.
5. **«закрыто (…)»** — стратегия вышла; у нас стоп-заявка брокера должна была сработать там же.

Две вещи, о которых нужно помнить:

* **Сигналы приходят с 07:00 до 23:50 и в выходные**, а отчёт пока лежит только файлом на сервере. Кто-то должен
  его видеть в течение получаса — без уведомлений вручную это нереально (предложение ниже).
* **Дивидендная отсечка.** Стоп-заявки брокера работают по фактическим ценам, а стратегия — по ценам с поправкой на
  дивиденд. Если позиция переходит через отсечку, стоп у брокера сработает на дивидендном гэпе. Перед отсечкой стоп
  нужно опустить на размер дивиденда. Будущие дивиденды в `data/dividends/moex_dividends.csv` добавлять только после
  отсечки — иначе отчёт покажет текущие цены с поправкой, а не биржевые.

### Контур целиком: бумажный прогон

Тот же код, что работает по cron, прогнан по часам 12.06–21.10 на тех минутах, какие были бы видны к каждому
запуску; вместо брокера — бумажный (рыночные заявки по минуткам биржи, стоп-заявки по минимуму минуты, комиссия
0.05%). Подробно — [paper_replay.md](paper_replay.md).

| вариант | поймано входов стратегии | итог на бумаге | итог стратегии |
|---|---|---|---|
| как было: запуск в :02 в будни 10–23 ч | 0 из 33 | 0% | +10.8% |
| после исправления, только будни 10–23 ч | 22 из 33 | +10.3% | +9.5% по тем же сделкам |
| **после исправления, все торговые часы (сейчас)** | **33 из 33** | **+11.6%** | **+10.8%** |

Вход — на 4 минуты позже стратегии и на 0.03% дороже (медиана), меньше заложенных в бэктест 0.05%. Стоп-лосс и
трейлинг-стоп закрывают сделки там же, где бэктест. В 36 случайных часах без сигнала контур ни разу не открыл
лишнего.

### Вход по API

Проверено без заявок (`scripts/tinvest_readonly_check.py`, 22.10): токен читается, счёт виден (брокерский, тариф
premium), SBER, GAZP, LKOH торгуются через API (лот 1 / 10 / 1, шаг цены 0.01 / 0.01 / 0.5), лимит — 600 запросов
свечей в минуту. **Заявок через API не отправлялось ни одной, песочница не открывалась** — это следующий шаг, когда
решим исполнять через API.

## Как предлагаю строить инференс дальше

Принципы:

1. **Один код с бэктестом.** Стратегия в инференсе — тот же расчёт, что в журнале экспериментов, без переписывания.
2. **Каждое решение — в журнал,** с моментом данных. Журнал — основа сверки с бэктестом и с нашими сделками.
3. **Раз в неделю — сверка:** пересчёт на новых данных; если решения журнала разошлись с бумажным прогоном —
   разбор до того, как торговать дальше.

Что добавить:

* **Уведомления в Telegram:** сообщение на «ОТКРЫТЬ», «закрыть по сроку» и тревогу здоровья; раз в день — сводка
  позиций. Без этого ручная торговля по часовым сигналам с утра до ночи и в выходные невозможна.
* **Журнал наших сделок:** файл, куда записываем свои покупки и продажи (время, бумага, цена, лоты). Раз в неделю —
  сравнение с журналом контура: пропуски, опоздания, проскальзывание.
* **Несколько стратегий в одном контуре:** в `configs/live.yaml` — список стратегий с правилом, бумагами, долей
  капитала и режимом (боевой / бумажный). Вторая стратегия — в бумажном режиме: сигналы считаем и пишем в журнал,
  не торгуем. Кандидаты по свежим данным — S45 (NR7 → пробой) и S46 (пробой 55 дней); для них инференс — через тот
  же движок перебора на живых файлах (признаки уже пересобираются, `scripts/fresh_strategies.py`).
* **Модели CatBoost в инференс пока не идут:** со всеми издержками они в минусе (H31, H58). Если модель пройдёт
  критерий — тот же путь: сохранённая обученная модель с отметкой данных, признаки на свежих данных тем же кодом,
  решение в том же формате, плюс проверка, что признаки в инференсе совпадают с бэктестом.
* **Резервная копия минуток:** раз в день копия `data/raw/live` в другое место.
* **Исполнение через API — позже:** `scripts/live_trade.py` готов (покупка по сигналу, стоп-лосс и трейлинг-стоп у
  брокера от фактической цены, продажа по сроку, тревоги при расхождениях), но ни разу не отправлял заявок. Порядок:
  песочница → боевой счёт малым объёмом.

Этапы:

| этап | что делаем | сколько | дальше, если |
|---|---|---|---|
| **0. Бумажный (сейчас)** | контур каждый час, сигналы в журнал, сделок нет; раз в неделю — сверка с бумажным прогоном | 2–4 недели | решения журнала совпадают с прогоном, сбор данных без пропусков |
| **1. Ручная торговля, малый объём** | мы исполняем по сигналам (лучше — по уведомлениям), записываем свои сделки | 1–3 месяца | проскальзывание ≤ 0.05% на сторону, нет пропущенных и лишних входов, здоровье в норме |
| **2. Исполнение через API** | после проверки в песочнице; `live_trade.py` с боевым счётом малым объёмом | после этапа 1 | заявки брокера совпадают с журналом |
| **3. Вторая стратегия, металлы** | S45 или S46 из бумажного режима; металлы — после решения по брокеру | после этапа 1 | 20–30 бумажных сделок, портфель лучше на единицу риска |

## Что решить вместе

1. **Кто получает сигналы и кто исполняет** — сигналы с 07:00 до 23:50 и в выходные. Делаем уведомления в Telegram?
2. **Капитал на бумагу и счёт** — отдельный счёт для стратегии или ИИС; тариф premium — какая комиссия на акции.
3. **Токен.** Сейчас у токена полный доступ к боевому счёту. На этапах 0–1 заявки через API не нужны — лучше
   заменить на токен «только чтение», торговый выпустить позже на отдельный счёт.
4. **Вторая стратегия в бумажный режим** — S45 или S46?
5. **Когда проверяем заявки в песочнице** — нужно перед этапом 2.
